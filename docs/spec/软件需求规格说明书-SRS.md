## 第 1 章 引言

### 1.1 编写目的

本文档基于对反编译 / 裁剪后的 Claude Code CLI 工程的源代码进行需求逆向而得，目的是为后续的产品交付、回归验收、合规审查、跨团队协作提供单一事实来源（Single Source of Truth）。读者包括：

- 产品经理 / 业务分析师，用于确认边界与补全未覆盖的场景；
- 前端 / 后端 / 平台开发，用于实现或重构时统一口径；
- QA 测试，用于设计测试用例与回归用例；
- 安全 / 法务 / 合规，用于评估授权、留存与可观测性。

### 1.2 产品定位

Claude Code 是一款面向开发者终端的智能编程助理 CLI。它通过自然语言与开发者的本地工程进行交互，提供代码编辑、命令执行、文件检索、网络拉取、子代理协作、权限审阅、上下文压缩、会话存档等能力，并把每一次交互以可审计、可回滚、可分享的形式沉淀。

产品使命：**让开发者用对话的方式完成工程任务，并把 AI 协作的成本、风险、过程变得可控、可追溯。**

产品边界：

- **属于**：本地工程读写、终端操作、API 调度、会话持久化、第三方协议（MCP）接入、可编程扩展（Hook）。
- **不属于（默认不开）**：可视 IDE、托管代理 SaaS（远程通道由受控标志启用）、语音 / 主动推送（受控标志启用）、图像 / 屏幕操控（已替换为占位包）。

### 1.3 术语与缩略语

| 术语 | 释义 |
|---|---|
| 会话（Session） | 用户一次完整的对话交互周期，包含消息、工具调用、文件改动、统计指标。 |
| 主循环（REPL） | 用户在终端中持续输入、模型持续回复的循环界面。 |
| 工具（Tool） | 由模型调用、在用户工程中执行的离散能力（如读文件、跑命令）。 |
| 斜杠命令（Slash Command） | 以 `/` 开头的本地命令，由 CLI 本地分发执行。 |
| 技能（Skill） | 带有前置元数据的可复用提示 / 工作流，可注入到子代理中执行。 |
| 钩子（Hook） | 用户定义的外部命令 / 回调，在特定生命周期事件触发。 |
| MCP | 模型上下文协议，用于连接外部工具 / 数据服务器。 |
| 权限模式（Permission Mode） | 控制工具调用是否需要用户确认的预设策略集合。 |
| 上下文压缩（Compact） | 对超出窗口的历史消息进行摘要重建，以延长会话。 |
| 沙箱（Sandbox） | 限制工具对文件系统和网络的访问范围。 |
| 文件历史（File History） | 对被工具改动的文件创建的本地可回滚快照链。 |
| 团队（Team） | 多代理以主从模式协作的临时组织，承载跨代理消息。 |
| 子代理（Subagent） | 由当前会话派生的、具备独立模型与上下文的子会话。 |
| 工作树（Worktree） | 基于 Git 的隔离工程目录，允许并行修改。 |

### 1.4 参考文档

- `docs/architecture/*`：架构总览（保留原文链接）。
- `docs/base/*`、`docs/context/*`、`docs/skill/*`、`docs/mcp/*`、`docs/hook/*`、`docs/permission/*`、`docs/repl/*`：分模块说明。

## 第 2 章 产品概述

### 2.1 目标用户与典型场景

| 角色 | 典型场景 |
|---|---|
| 个人开发者 | 在本地仓库里让助手帮忙改 bug、解释代码、跑测试、提交 PR。 |
| 团队维护者 | 配置共享权限规则、钩子、Skill，让协作者在统一的安全边界内使用助手。 |
| 企业管理员 | 通过托管设置下发可用模型、可用 MCP 服务器、可用插件集合、强制登录方式。 |
| 自动化 / CI 集成方 | 在无人值守场景下调用 Claude Code，使用受限 token 完成只读或受控写操作。 |
| 高级开发者 | 编写 Skill / Hook / Plugin，把助手的能力封装为团队资产。 |

### 2.2 产品形态与运行模式

- **交互模式**：终端 REPL，进入即用。用户输入自然语言，模型在终端中回复并可能调用工具。
- **管道模式**：通过 `-p` 选项一次性传入提示，无交互输出，常用于脚本 / CI。
- **打印模式**：纯文本打印结果，不进入交互界面。
- **远程模式**：受控标志启用，连接到托管会话，断线可恢复。
- **代理 / SDK 模式**：作为嵌入式智能体供宿主应用驱动，仅暴露 API 入口。

### 2.3 模块全景

```
┌──────────────────────────────────────────────────────────┐
│                  会话入口 / 启动与初始化                  │
│   CLI 参数解析 → 配置加载 → 信任确认 → 屏幕渲染            │
└──────────────────────────────────────────────────────────┘
                            │
        ┌───────────────────┼────────────────────────────┐
        ▼                   ▼                            ▼
   REPL 主循环         模型与配额                 工具执行引擎
        │                   │                            │
        ▼                   ▼                            ▼
  消息流 / 斜杠命令   用量 / 速率限制 / 计费       文件 / Shell / 网络
        │                                              │
        ▼                                              ▼
  子代理 / 团队协作                              权限 / 钩子 / 钩子结果
        │
        ▼
   上下文压缩 / 文件历史 / 会话存档
```

## 第 3 章 角色与权限需求

### 3.1 角色定义

产品中所有动作均以"人 + 上下文"为权限主体，识别为以下角色：

| 角色编号 | 名称 | 典型身份 | 能力范围 |
|---|---|---|---|
| R-END-USER | 终端用户 | 任意合法产品使用者 | 全部用户级操作 |
| R-TEAM-LEAD | 团队主代理 | 会话内被提升为主代理的代理实例 | 管理团队成员、接受审批 |
| R-TEAM-MEMBER | 团队成员代理 | 团队内的子代理 | 在团队上下文中发收消息 |
| R-ENTERPRISE-ADMIN | 企业管理员 | 通过托管设置下发策略 | 模型、插件、市场强制生效 |
| R-SDK-CONSUMER | SDK 集成方 | 将 CLI 作为库嵌入的程序 | 触发受限提示、监听流式事件 |
| R-CI-RUNNER | 自动化调用方 | CI 中持有受限 token 的程序 | 受限的只读 / 受控写场景 |
| R-MCP-SERVER | MCP 服务器 | 通过协议暴露工具 / 数据 | 由权限规则约束 |

### 3.2 权限维度

权限控制贯穿 **资源** × **动作** × **主体** × **上下文** 四个维度：

- **资源**：文件（路径或通配）、目录、URL、命令前缀、MCP 服务器、技能、钩子事件、模型、计划。
- **动作**：执行（execute）、读写（read / write）、询问（ask）、拒绝（deny）、旁路（passthrough）。
- **主体**：用户、CLI 实例、子代理、远程代理、CI 调用方。
- **上下文**：当前会话 ID、当前工作目录、附加目录、当前权限模式、当前模型、勾选的项目设置。

### 3.3 工具执行授权矩阵

下表是 **默认情况** 下用户面对工具调用时的可选策略集合。具体决定规则见 §4.3 各工具条目。

| 工具分类 | 默认行为 | 用户可选的「立即决策」 |
|---|---|---|
| 只读文件 / 检索类 | 允许 | （无需决策） |
| 写入 / 编辑 / Shell | 询问 | 一次性允许 / 永久允许 / 拒绝 / 编辑后允许 |
| 网络抓取 | 询问（白名单外） | 同上 |
| 子代理 / 计划 / 工作树切换 | 询问 | 同上 |
| 配置变更 | 询问或拒绝 | 一次性允许 / 永久允许 / 拒绝 |
| 后台任务控制 | 允许 | （无需决策） |
| 账号与认证类 | 强制走 OAuth | 同上 |

> *永久允许*会以"项目设置 / 用户设置 / 本地设置 / 策略设置"之一落盘；详见 §3.5。

### 3.4 权限模式

产品提供以下五种**用户可显式切换**的权限模式。所有未永久放行的工具在不同模式下表现不同：

| 模式 | 业务定位 | 关键行为 |
|---|---|---|
| acceptEdits | 信任编辑 | 自动放行"安全"的本地文件编辑类操作，仍询问其他工具 |
| bypassPermissions | 全力模式 | 不询问，但敏感路径（版本控制 / CLI 配置目录 / Shell 配置）仍强制询问 |
| default | 默认 | 按规则匹配，未匹配则询问 |
| dontAsk | 严格 | 未匹配则直接拒绝 |
| plan | 计划 | 仅允许只读工具，编辑 / 执行被严格限制 |
| auto（受控标志） | AI 自动审批 | 由后台分类模型在静默评估后自动放行 / 拒绝 |

附加的内部模式 "bubble" 用于团队成员之间的隔离上下文，不作为用户配置入口。

### 3.5 规则来源优先级

权限规则按以下优先级生效（数字小者优先级高）：

1. CLI 命令行参数（`cliArg`）
2. 当前会话中临时注册（`session`）
3. 策略设置（`policySettings`，企业托管下发）
4. 用户设置（`userSettings`，全局用户级）
5. 项目设置（`projectSettings`，随仓库提交）
6. 本地设置（`localSettings`，本地覆盖，不入版本）
7. 标志级设置（`flagSettings`，启动时由外部注入）

> 项目设置允许共享约定；本地设置覆盖项目；用户设置跨项目生效；策略设置对下层均生效。

### 3.6 钩子可见性约束

- 所有钩子在用户未确认"工作区信任"前 **不执行**。
- 若当前处于"仅托管钩子"白名单模式（`allowManagedHooksOnly`），项目 / 用户配置的钩子被屏蔽。
- 钩子可读环境变量有限，仅暴露工程根、插件根、钩子事件相关上下文，绝不暴露 OAuth Token、API Key、用户敏感字段。

## 第 4 章 功能性需求

> 每个功能均按以下结构定义：使用角色 / 前置条件 / 操作流程 / 正常结果 / 异常场景。

### 4.1 会话与启动

#### 4.1.1 会话启动

- **使用角色**：R-END-USER
- **前置条件**：CLI 已安装；可选：当前目录为 Git 仓库或可识别工程根。
- **操作流程**：
  1. 用户在终端执行 CLI 启动命令。
  2. 系统判定是否首次使用、是否需要初始化账号。
  3. 系统执行"信任工作区"提示（如未确认过）。
  4. 系统加载可用模型、可用 MCP、可用插件、可用 Skill、可用 Hook。
  5. 系统加载并展示 REPL 界面等待输入。
- **正常结果**：进入主循环；用户可输入自然语言或斜杠命令。
- **异常场景**：
  - 未登录且策略不允许匿名访问 → 引导完成登录。
  - 工作区未信任且含不可信钩子 → 询问是否依然加载。
  - 设置文件格式错误 → 报告错误并禁用对应规则。
  - 模型不可用 → 提示用户切换，回退到默认模型。

#### 4.1.2 会话恢复

- **使用角色**：R-END-USER
- **前置条件**：历史上存在至少一次会话存档。
- **操作流程**：
  1. 用户输入恢复命令 `[/resume / /continue]` 或在启动参数中指定会话 ID。
  2. 系统列出可选历史会话（按时间倒序，可筛选）。
  3. 用户选择目标会话。
  4. 系统载入该会话的全部历史消息、文件改动快照、上次统计指标。
- **正常结果**：REPL 恢复至上次状态，可继续对话。
- **异常场景**：
  - 历史存档格式不兼容 → 提示并拒绝加载。
  - 历史对话中的旧模型不可用 → 自动重新映射或保留沉默。
  - 文件快照已过期 → 仍可载入，但不保证可回滚。

#### 4.1.3 会话退出

- **使用角色**：R-END-USER
- **前置条件**：无强制后台任务正在运行（或用户确认放弃）。
- **操作流程**：`/exit / /quit` 或收到终端 EOF。
- **正常结果**：写入最终统计指标、清理临时文件、释放后台任务。
- **异常场景**：
  - 后台任务仍在运行 → 询问是否停掉并退出。
  - 进程信号被拦截 → 触发二次确认。

### 4.2 对话主循环（REPL）

#### 4.2.1 自然语言输入与提交

- **使用角色**：R-END-USER
- **前置条件**：CLI 已登录且网络可达（若是云端模型）。
- **操作流程**：
  1. 用户键入内容，可附加附件（图片、文本文件、剪贴板内容）。
  2. 提交后系统附加上下文（工程结构、CLAUDE.md、近期改动），组成本轮请求。
  3. 模型持续流式回复；可能插入工具调用。
  4. 工具调用所需权限被处理；结果合并入对话流。
  5. 模型结束当前轮；REPL 回到等待输入。
- **正常结果**：用户看到完整对话、文件改动、运行命令输出。
- **异常场景**：
  - API 超时 / 限流 → 自动回退 / 退避重试，必要时提示用户。
  - 上下文超出窗口 → 触发自动压缩。
  - 模型拒绝服务（内容策略） → 给出原因摘要，要求用户改写。
  - 工具被拒绝 → 反馈给模型，由模型继续决策。

#### 4.2.2 后台运行（Ctrl+B / 二段背景化）

- **使用角色**：R-END-USER
- **操作流程**：
  1. 用户按快捷键，请求将当前会话转入后台。
  2. 系统在内存中冻结会话，并开启一个独立监控任务。
  3. 主循环恢复至新输入；用户可继续其他对话。
  4. 后台任务完成或失败时通过通知中心报告。
- **正常结果**：用户在前台不被打断；后台完成后再回看。
- **异常场景**：
  - 后台失败 → 通知展示失败原因与部分输出。
  - 进程退出前未清理 → 依赖进程级清理钩子。

#### 4.2.3 取消与重试

- **使用角色**：R-END-USER
- **操作流程**：在模型 / 工具执行中按 Esc / Ctrl+C。
- **正常结果**：当前请求被中止，工具的副作用回滚至安全状态。
- **异常场景**：
  - 取消后模型继续发送无效片段 → 自动截断。
  - 工具已落盘而无法回滚 → 提示用户使用文件历史回滚。

#### 4.2.4 Vim 模式 / 复用历史 / 选择复制

- **使用角色**：R-END-USER
- **前置条件**：用户在设置中开启或在初次启动选择启用。
- **操作流程**：在输入框进入 Vim 模式；使用 j / k / a / i / Esc 等键编辑；方向键浏览历史；选中即复制。
- **正常结果**：提升键入效率；不打断主流程。
- **异常场景**：与终端能力冲突时退化为标准输入模式。

### 4.3 工具能力

工具是产品能力的核心单元。每条工具都需描述其使用方式、参数语义、产物、是否需要授权、是否可并行、是否可异步。

#### 4.3.1 文件与代码编辑

##### 4.3.1.1 读取文件（Read）

- **角色**：R-END-USER / 子代理 / 团队代理
- **前置条件**：目标路径在允许范围内。
- **操作流程**：给出绝对路径，可选行范围或 PDF 页范围 → 工具返回文本 / 图片 / PDF / Notebook 内容。
- **正常结果**：读取的内容以分段方式进入上下文。
- **异常场景**：
  - 文件不存在 → 提示相近文件名提示。
  - 二进制 / 受限设备文件 → 拒绝并说明。
  - 单次读取过大 → 截断并提示换行 / 分页。

##### 4.3.1.2 写入文件（Write）

- **角色**：R-END-USER（确认后）
- **前置条件**：目录存在；用户已批准或处于合法模式。
- **操作流程**：给出路径与完整内容 → 生成差异预览 → 用户确认 → 写入文件并产生文件历史快照。
- **正常结果**：文件被覆盖，光标处产生可回滚版本。
- **异常场景**：
  - 目录不存在 → 提示先创建。
  - 文件在写入前被外部修改 → 二次确认是否覆盖。
  - 超过大小阈值 → 拒绝并提示拆写。

##### 4.3.1.3 编辑文件（Edit）

- **角色**：R-END-USER（确认后）
- **前置条件**：目标文件存在；`old_string` 唯一匹配。
- **操作流程**：提供旧串与新串或全文替换 → 唯一性校验 → 差异展示 → 用户确认 → 写入。
- **正常结果**：文件中匹配片段被替换；其他内容不变。
- **异常场景**：
  - 旧串零或多匹配 → 拒绝，给出可见性改善建议。
  - 文件超过大小限制 → 拒绝。
  - 编辑过程中外部修改 → 拒绝，提示重新读入。

##### 4.3.1.4 笔记本编辑（NotebookEdit）

- **角色**：R-END-USER（确认后）
- **前置条件**：`.ipynb` 文件路径合法；单元格 ID 合法。
- **操作流程**：选择模式（replace / insert / delete）、目标单元格、新内容 → 检查 → 用户确认 → 持久化。
- **正常结果**：指定单元格按所选模式被修改。
- **异常场景**：单元格不存在 / Notebook 结构损坏 → 明确报错。

##### 4.3.1.5 文件通配检索（Glob）

- **角色**：R-END-USER / 子代理
- **前置条件**：只读，无需授权。
- **操作流程**：给出通配模式与搜索根 → 返回匹配路径列表。
- **正常结果**：路径数组（封顶 100 个）。
- **异常场景**：命中数被截断时附带"已截断"标志。

##### 4.3.1.6 文件内容检索（Grep）

- **角色**：R-END-USER / 子代理
- **前置条件**：只读，无需授权。
- **操作流程**：给出正则、检索路径、过滤与上下文选项 → 返回行命中或文件命中列表。
- **正常结果**：命中数组，可附带前后文。
- **异常场景**：默认上限内截断；可手动提高上限。

#### 4.3.2 系统交互

##### 4.3.2.1 Shell 命令执行（Bash）

- **角色**：R-END-USER（确认后）
- **前置条件**：当前为合法权限模式；沙箱规则允许该命令。
- **操作流程**：给定命令与可选超时 → 子命令解析 → 风险评级 → 用户确认（或规则放行）→ 执行 → 返回标准输出、错误输出、退出码。
- **正常结果**：命令运行；输出进入上下文。
- **异常场景**：
  - 命令被沙箱拦截 → 展示策略说明，建议走绕过流程。
  - 命令包含 UNC 路径 → 直接拒绝。
  - 读 / 写模式判断失误 → 进入"看似读但实际写"路径并强制询问。
  - 超时仍未完成 → 询问用户是否再等或终止。
  - 后台执行 → 切换为轮询 / 通知，详见 §4.11。

##### 4.3.2.2 PowerShell 执行（PowerShellTool）

- **角色**：R-END-USER（受控开启）
- **前置条件**：目标运行环境启用了 PowerShell 通道。
- **操作流程**：同上但执行环境为 PowerShell。
- **正常结果**：与 Bash 等价。
- **异常场景**：与 Bash 一致；并在 auto 模式下启用 AI 分类器进行读写识别。

#### 4.3.3 网络与检索

##### 4.3.3.1 网页搜索（WebSearch）

- **角色**：R-END-USER（隐式授权）
- **前置条件**：系统已连接云端模型且具备联网能力。
- **操作流程**：给定查询、域名白 / 黑名单 → 调用方返回结构化结果。
- **正常结果**：标题、摘要、URL 列表。
- **异常场景**：
  - 单轮 8 次上限 → 超额部分不执行。
  - 黑名单域名 → 在结果中被过滤但不报错。

##### 4.3.3.2 网页抓取（WebFetch）

- **角色**：R-END-USER（按主机名授权）
- **前置条件**：URL 合法；目标主机在白名单外需用户确认。
- **操作流程**：给定 URL 与处理提示 → 抓取 → Markdown 转换 → 模型分析 → 摘要返回。
- **正常结果**：分析后摘要 + 状态码。
- **异常场景**：
  - 网络不可达 → 报告超时。
  - 主机名未授权 → 询问。
  - 返回超过 100k 字符 → 自动落盘并在上下文中以引用形式呈现。

#### 4.3.4 会话与历史

##### 4.3.4.1 提问（AskUserQuestion）

- **角色**：模型 → 用户
- **前置条件**：模型判定需要用户澄清。
- **操作流程**：呈现 1–4 个互斥选项（可多选） → 用户作答 → 结果回传。
- **正常结果**：选项答案进入上下文；模型基于答案继续。
- **异常场景**：超时未作答 → 模型收到"无答复"标记继续。

##### 4.3.4.2 文件快照回滚（隐含于 `/rewind` 与文件历史）

- **角色**：R-END-USER
- **前置条件**：当前会话有过文件历史。
- **操作流程**：用户把光标移回某轮 → 触发"回到此处"。
- **正常结果**：被改动的文件恢复至该轮之前状态；后续模型消息从会话中剪除。
- **异常场景**：
  - 文件已被外部改动且与历史冲突 → 询问是否覆盖。
  - 备份链断裂 → 报告并拒绝。

#### 4.3.5 子代理与团队协作

##### 4.3.5.1 派生子代理（Agent）

- **角色**：R-END-USER
- **操作流程**：给定任务摘要、详细提示、可选子代理类型与模型、可选异步与隔离方式 → 派生新会话；可阻塞等待或后台。
- **正常结果**：子代理独立完成任务并把最终答复返回到主会话。
- **异常场景**：
  - 异步启动超过 15 秒 → 自动转为后台；用户可稍后查看。
  - 子代理失败 / 超时 → 主会话收到失败说明与可选部分输出。
  - 子代理权限受限于父会话模式。

##### 4.3.5.2 发送消息（SendMessage）

- **角色**：R-TEAM-MEMBER / R-END-USER
- **操作流程**：选择收信人（单名 / 广播 / 桥接 ID / 域套接字路径）与消息体（自由文本或结构化停机 / 审批请求）→ 投递。
- **正常结果**：收件代理收到消息并按业务逻辑响应。
- **异常场景**：
  - 收件人不存在 → 报告。
  - 结构化消息解析失败 → 报告。

##### 4.3.5.3 后台任务停止（TaskStop）

- **角色**：R-END-USER
- **操作流程**：按任务 ID 发起停机。
- **正常结果**：后台任务收到终止信号并清理。
- **异常场景**：任务 ID 不存在或已结束 → 报告。

##### 4.3.5.4 后台任务输出（TaskOutput）

- **角色**：R-END-USER
- **操作流程**：按任务 ID 与等待超时拉取当前输出。
- **正常结果**：最新输出（含错误）。
- **异常场景**：任务未产出可用输出 → 报告"暂未就绪"。

#### 4.3.6 计划与工作树

##### 4.3.6.1 进入计划模式（EnterPlanMode）

- **角色**：R-END-USER
- **前置条件**：当前未在子代理内；多通道未激活。
- **操作流程**：切到只读状态，模型只能做发现 / 设计。
- **正常结果**：进入 plan 模式，只读工具可用。
- **异常场景**：在不允许场景下拒绝。

##### 4.3.6.2 退出计划模式（ExitPlanMode）

- **角色**：R-END-USER
- **操作流程**：给出当前计划文本与可选的工具级白名单请求 → 用户审阅 → 同意 / 拒绝 → 回到默认模式并应用白名单。
- **正常结果**：计划批准，工具按白名单放行。
- **异常场景**：用户拒绝 → 留在 plan 模式，可改写后再次提交。

##### 4.3.6.3 进入工作树（EnterWorktree）

- **角色**：R-END-USER（受控标志开启）
- **前置条件**：当前已是 Git 仓库；尚未在工作树中。
- **操作流程**：指定工作树名 → 创建并切入。
- **正常结果**：后续所有改动发生在新目录；退出后回到原路径。
- **异常场景**：冲突或重名 → 报告。

##### 4.3.6.4 退出工作树（ExitWorktree）

- **角色**：R-END-USER（受控标志开启）
- **操作流程**：指定保留或移除以及是否丢弃改动。
- **正常结果**：释放工作树目录；保留模式下原目录不变。
- **异常场景**：有未提交改动且未确认丢弃 → 拒绝移除。

#### 4.3.7 配置与运行环境

##### 4.3.7.1 配置读写（Config）

- **角色**：内部用户
- **前置条件**：仅在受信任用户态下启用。
- **操作流程**：按 key 读取或写入配置 → 立即生效或失败。
- **正常结果**：返回当前值或操作成功。
- **异常场景**：key 不可写 → 拒绝。

##### 4.3.7.2 LSP（语言服务协议）

- **角色**：R-END-USER
- **前置条件**：受控开关启用；当前 IDE 插件可用。
- **操作流程**：按 LSP 方法调用 → 返回诊断 / 补全等。
- **正常结果**：返回 IDE 级语言服务结果。
- **异常场景**：LSP 守护未启动 → 报告并退化为只读工具。

##### 4.3.7.3 任务清单（TodoWrite / TaskCreate 系列）

- **角色**：R-END-USER / 子代理
- **操作流程**：维护一组当前任务项的状态（pending / in_progress / completed）；可设置依赖与归属。
- **正常结果**：列表展示给用户；当所有项完成时清空；3 项以上完成未复核时给出复核提醒。
- **异常场景**：依赖闭环错误 → 报告。

### 4.5 技能（Skill）体系

- **业务定位**：让用户用 Markdown 编写一次性的指令 / 工作流，并能被模型调用。
- **使用角色**：所有。
- **存储位置**：
  - 仓库内：`.claude/skills/<name>/SKILL.md`（项目设置）
  - 用户：`<HOME>/.claude/skills/<name>/SKILL.md`（用户设置）
  - 企业托管：策略下发
  - 旧版：`<HOME>/.claude/commands/*.md`
- **元数据字段**：
  - `name` / `description` / `when_to_use`
  - `allowed-tools` / `argument-hint` / `arguments`
  - `user-invocable` / `disable-model-invocation`
  - `model` / `effort`
  - `hooks`（本技能自带的钩子集合）
  - `context`：`inline` 注入主线程 / `fork` 派生子线程
  - `agent` / `paths` / `shell`
- **调用方式**：
  - 用户显式：以 `/<skill-name>` 触发。
  - 模型隐式：模型判定匹配时主动注入并执行。
- **动态发现**：监听 `.claude/skills/` 变化；按已访问路径激活条件化 Skill。
- **派生执行**：选中 `fork` 模式的 Skill 在独立代理中运行，token 配额与权限独立。
- **正常结果**：把技能内的提示与钩子注入到执行上下文，按配置运行。
- **异常场景**：
  - 元数据缺失或非法 → 技能被禁用并报告。
  - 路径条件未匹配 → 静默跳过。

### 4.6 钩子（Hook）扩展机制

- **业务定位**：让用户在产品生命周期的关键时刻嵌入自定义逻辑。
- **触发事件（节选）**：
  - 工具调用前 / 后 / 失败：`PreToolUse` / `PostToolUse` / `PostToolUseFailure`
  - 用户输入提交：`UserPromptSubmit`
  - 会话：`SessionStart` / `SessionEnd` / `Setup`
  - 主循环结束：`Stop` / `StopFailure`
  - 子代理：`SubagentStart` / `SubagentStop`
  - 权限拒绝：`PermissionDenied`
  - 无头代理权限请求：`PermissionRequest`
  - 提示征询：`Elicitation` / `ElicitationResult`
  - 文件系统变更：`CwdChanged` / `FileChanged`
  - 工作树：`WorktreeCreate`
  - 上下文压缩：`PreCompact` / `PostCompact`
  - 任务协作：`TeammateIdle` / `TaskCreated` / `TaskCompleted`
  - 配置：`ConfigChange` / `InstructionsLoaded`
  - 通知：`Notification`
- **钩子类型**：
  - `command`：在子 Shell 中跑命令行并解析输出。
  - `prompt`：作为提示调用模型判断。
  - `agent`：委派给子代理。
  - `http`：向指定 HTTP 地址发送请求。
  - `callback` / `function`：宿主程序内嵌回调。
- **匹配条件**：通过 `matcher` 限定（如 `Bash(git *)`）只触发相关工具 / 子命令。
- **运行环境**：
  - 默认 Shell：bash；Windows 强制使用 Git Bash。
  - PowerShell：使用 `pwsh -NoProfile -NonInteractive`。
  - 默认超时：10 分钟；`SessionEnd` 类最快 1.5 秒。
- **写入约定**：
  - 通过 stdout 输出 JSON 决定后续动作（如拦截、改写、附加上下文）。
  - 退出码 2 视为阻塞错误，加入异步通知队列。
- **安全约束**：
  - 工作区未信任前全部禁用。
  - 受控策略下，仅允许受托管钩子生效。
  - 可注入的环境变量受限（详见 §3.6）。
- **正常结果**：钩子按预期顺序生效，并把 `additionalContext` 等附加信息合入上下文。
- **异常场景**：
  - 子进程 EPIPE → 静默忽略。
  - 超时 → 标记为非阻塞错误并继续。
  - JSON 解析失败 → 报告并降级为非阻塞错误。

### 4.7 MCP 协议服务器

- **业务定位**：通过标准协议对接外部工具 / 数据源。
- **接入来源**：本地配置、项目 `.mcp.json`、用户 / 企业策略、Claude.ai 已注册服务、动态命令行参数。
- **传输方式**：stdio、SSE、SSE-IDE、HTTP、WebSocket、WebSocket-IDE、SDK、Claude.ai 代理。
- **生命周期**：
  1. 加载所有配置，按作用域过滤。
  2. 尝试建立连接，捕获状态：连接成功 / 失败 / 待授权 / 待激活 / 已禁用。
  3. 成功连接后枚举服务器能力（工具 / 命令 / 资源 / 提示）。
  4. 失败时按 1s → 2s → 4s → 8s → 16s 退避重连，最多 5 次，单次最长 30 秒。
  5. 监听服务器通知（`tools/list_changed` 等）即时刷新本地缓存。
- **鉴权**：
  - 标准 OAuth：PKCE + 授权码 + 本地回调。
  - 跨 App 访问（XAA / SEP-990）：RFC 8693 令牌交换。
  - 访问令牌按服务器指纹分别存储；锁文件防止并发刷新。
  - 检测到 `insufficient_scope` 时进入 step-up 授权。
- **调用方式**：模型侧把 MCP 工具视作一等公民工具，与内置工具走同一套权限与渲染管线。
- **正常结果**：用户可使用 MCP 提供的所有能力。
- **异常场景**：
  - 证书 / 网络问题 → 退避重试或标记 `failed`。
  - 令牌过期 → 静默刷新，必要时强制重新登录。
  - 服务端违反协议 → 上报并短暂禁用。

### 4.8 插件与市场

- **业务定位**：把"命令、技能、代理、MCP、LSP、钩子、设置片段"的集合打包成可分发资产。
- **关键路径**：
  - **市场**：受控白名单内的 Git 仓库清单（默认或企业扩展）。
  - **插件**：从市场克隆到本地，由 manifest 驱动加载。
  - **启用**：依据用户设置 + 策略过滤后启用。
- **生命周期**：发现 → 下载 → 校验 manifest → 解析子模块路径 → 注入命令 / 技能 / 钩子 / MCP / LSP → 注册到 REPL。
- **正常结果**：插件命令与新能力即时可用。
- **异常场景**（按错误码分类）：
  - 路径找不到 / Git 鉴权失败 / 超时 / 网络错误。
  - manifest 解析 / 校验失败。
  - 插件或市场在策略中被禁用 / 拦截。
  - MCP / LSP 子模块配置非法或启动失败。
  - 钩子加载失败。
  - 缓存未命中 → 重新拉取。
  - 组件加载失败 → 报告并跳过该组件。

### 4.9 输出风格（Output Style）

- **业务定位**：切换模型在回复时使用的写作 / 结构规则。
- **存储**：项目与用户 `output-styles/*.md`。
- **元数据**：`name` / `description` / `keep-coding-instructions`（是否保留 CLAUDE.md 中的代码指令）。
- **正常结果**：选定风格作为系统提示附加。
- **异常场景**：风格文件格式错误 → 报告并继续使用上一可用风格。

### 4.10 认证与账号

- **业务定位**：让 CLI 安全持有访问 Anthropic（或其代理）的凭据。
- **认证渠道**（按优先级）：
  1. 命令行 `--bare` 模式下仅使用 `--settings` 注入的助手。
  2. 托管 OAuth 上下文（远程模式下）。
  3. 短寿命环境变量令牌。
  4. 文件描述符令牌（远程回退）。
  5. 用户设置中的命令式助手（执行 `apiKeyHelper` 获得 Key）。
  6. Claude.ai 已登录的 OAuth 令牌。
  7. macOS Keychain 持久化 API Key。
  8. 用户设置中的静态 API Key。
- **提供商**：Anthropic 自身 / AWS Bedrock / GCP Vertex / Foundry。
- **跨进程刷新**：通过 `.credentials.json` 的 mtime 感知刷新。
- **OAuth 令牌**：快过期 5 分钟内主动刷新；401 触发强制重读 keychain 并刷新。
- **强登校验**：当策略下发强制登录组织时必须匹配。
- **正常结果**：凭据准备就绪，可调用模型。
- **异常场景**：
  - 没有可用渠道 → 引导登录。
  - 令牌被吊销 → 报告并清理本地缓存。
  - 组织不匹配 → 阻止登录。

### 4.11 后台任务与计划任务

- **任务类型**：本地 Shell 任务、本地代理任务、远程代理任务、进程内队友任务、本地工作流任务、MCP 监控任务、长生命周期 Dream 任务。
- **执行流程**：
  1. 注册任务并分配 ID。
  2. 异步调度并把输出写入 per-task 文件。
  3. UI 中通过 `/tasks` 列表展示状态。
  4. 状态变更（成功 / 失败 / 停止）触发通知。
- **计划任务（Cron）**：
  - 由用户在 REPL 中声明（受控标志）。
  - 调度按 cron 表达式，叠加抖动避免尖峰。
  - 可绑定到具体代理。
- **正常结果**：任务在指定时刻触发并完成。
- **异常场景**：
  - 表达式非法 → 拒绝保存。
  - 进程退出 → 自动清理。

### 4.12 文件历史与回滚

- **业务定位**：让用户对每次写入都有"撤销"的把握。
- **能力**：
  - 每一次被授权的写入（编辑 / 写入 / 受控 Bash）在执行前自动建立快照。
  - 通过 `/rewind` 把光标回滚到指定轮，文件与会话一致回退。
- **正常结果**：本地存储的可回滚链随一次写入不断增长。
- **异常场景**：备份链失效 → 标记不可回滚。

### 4.13 上下文压缩（Compact）

- **业务定位**：在上下文接近窗口上限时做摘要，让会话继续可用。
- **策略选择**（在执行时动态决定）：
  - **会话级总结**：以当前会话为粒度生成摘要。
  - **微压缩**：只裁剪中间历史，保留起止。
  - **传统摘要**：把长会话合并为单条总结消息。
- **正常结果**：上下文重新容纳可用空间，模型可继续。
- **异常场景**：
  - 摘要超长 → 用压缩摘要嵌套策略。
  - 用户主动触发 → 同样生效。

### 4.14 通知与空闲摘要

- **业务定位**：让用户在离开时也能掌握助手 / 后台任务的进展。
- **通知内容**：模型侧主动摘要（"空闲时一段状态总结"）、系统级 OS 通知、跨进程队友消息。
- **正常结果**：用户回到终端即可看到要点。
- **异常场景**：通知权限被拦截 → 退化为 REPL 内通知徽标。

### 5.5 后台任务

## 第 6 章 非功能性需求

### 6.1 性能

| 指标 | 要求 |

| MCP 重连 | 最多 5 次，单次最大 30 秒 |
| 文件历史快照体积 | 单文件 1GB 上限 |

### 6.2 可靠性与可恢复性

- **断线重连**：远程 / 桥接模式下进入 `reconnecting`，UI 提示并保留会话状态。
- **进程退出清理**：注册清理钩子清理后台任务、释放句柄、关闭 MCP。
- **优雅中止**：中止信号传播到所有子代理、子进程、钩子。
- **崩溃恢复**：基于项目级配置可恢复累计费用、上次模型用量、上次持续时间。
- **锁文件**：跨进程令牌刷新用 lockfile 串行化。
- **文件历史可回滚链**：每次写入前自动备份，支持 `/rewind` 一键回退。

### 6.3 安全性

| 场景 | 要求 |
|---|---|
| API Key / OAuth Token 存储 | 用户态走系统 Keychain；企业态走受托管存储；裸 Token 不入日志、不入设置明文 |
| 凭据从文件描述符读取 | 避免落到命令行历史与环境变量 |
| bash 子命令解析 | 区分读 / 写，避免安全误判 |
| 敏感路径强制询问 | `.git/`、`.claude/`、`.vscode/`、Shell 配置 等在旁路模式仍询问 |
| 沙箱 | 默认对命令做读 / 写域隔离；对网络可选 |
| UNC 路径 | 直接拦截 |
| Hook 工作区信任前置 | 未确认信任前所有钩子静音 |
| MCP OAuth | PKCE + 回调；令牌按服务器指纹分存 |
| XAA | RFC 8693 令牌交换 |
| 平权限拦截 | 始终拒绝规则不可被旁路 |
